# AI 工作流案例：用 AI 開發機率模型與模擬工具，並用獨立方法驗證 AI 的產出

## 應用情境

從一段文字描述的老虎機規則開始，做出規格文件、理論 RTP、模擬器、統計驗收和回歸測試。AI（Claude Code / Cursor）負責大部分的程式撰寫；**正確性不能靠 AI 自己說對**，而是靠數學和獨立實作來證明。

## 流程

| 步驟 | AI 做的事 | 我做的事（把關點） |
|---|---|---|
| 1. 規則轉規格 | 把文字規則整理成 YAML：賠率表、線型、Wild/Scatter 規則、免費遊戲 | 補上**計算口徑**：RTP 以總押注為分母、免費遊戲獎金算進觸發它的那一局、Scatter 以總押注計 |
| 2. 理論模型 | 撰寫解析計數程式 | 先自己推導公式（線獎期望值、Poisson-binomial、T = 10/(1−10p)），再核對程式是否照公式寫 |
| 3. 模擬器 | 產生 Python 向量化模擬器 | 要求另一個語言（C++）**從規格重寫一份**，不共用任何程式碼 |
| 4. 交叉驗證 | 產生窮舉與比對程式 | 定義驗收標準：理論 vs 窮舉必須**精確相等**；Python vs C++ 逐盤面 100% 相同；MC 用 CI 判定 |
| 5. 統計判讀 | 計算 CI、z 值 | 根據 σ 規劃樣本量；用多個種子確認 CI 有校準好（≈95% 涵蓋） |
| 6. 回歸 | 產生 pytest | 決定哪些值要鎖成 golden；建立「改參數 → 重跑 → 檢查報告 → 才更新 golden」的流程 |

## 抓到的 AI 產出問題（實際紀錄）

| # | 問題 | 類型 | 怎麼發現 | 處理 |
|---|---|---|---|---|
| 1 | C++ 命中率判斷用了 `ns`（Scatter 數），但這個變數在免費遊戲迴圈裡被覆寫成最後一次免費遊戲的值 | 程式錯誤 | 審查程式碼時追蹤變數生命週期；如果漏掉，C++ 命中率會和窮舉的精確值不一致 | 觸發當下先存成 `triggered` 布林值 |
| 2 | Scatter 公式 q = 3·#S / L 隱含「每軸畫面最多出現一個 S」的假設，但沒有任何程式保證這件事 | 模型假設錯誤 | 推導公式時檢查前提條件 | 產生輪帶時加入間隔 ≥ 3 的限制，`model.validate()` 也會檢查 |
| 3 | 線獎規則「取所有符號中最大者」和「取第一個非 Wild 符號」在這份賠率表下結果相同，但只是因為 Wild 的賠率最高，換一份賠率表就會出錯 | 規格模糊 | 撰寫單元測試時舉反例 | 規格明文寫出規則；單元測試涵蓋 `WWW L4 L4`、`WW S ..` 等邊界情況 |
| 4 | 初版輪帶的理論 RTP 只有 67.7%，離目標的 96% 左右很遠 | 參數設計 | 理論模型一跑就看出來 | 用理論模型搜尋符號配置，不靠模擬試錯 |
| 5 | 用 `rng.integers(0, L-1)` 抽停輪位置（numpy 的上限不含 L−1），最後一格永遠抽不到 | 抽樣錯誤（常見寫法錯誤） | 列為突變測試：RTP z = +7.7、卡方 p ≈ 0 | 卡方檢定加進驗收清單 |

> 第 5 項是刻意植入的突變測試，用來證明流程抓得到這一類錯誤。

## 驗證方法

- **理論 = 窮舉，精確相等**（有理數比對，不是「差不多」）
- **跨實作逐盤面比對**：20 萬組隨機盤面，Python 和 C++ 的獎金與 Scatter 數必須完全相同。小 bug 在蒙地卡羅的雜訊裡可能看不出來，但在逐盤面比對下一定會現形
- **CI 驗收 + 校準檢查**：20 個種子的 z 值應該近似標準常態
- **突變測試**：4 種 bug 全部被抓到；同時算出每種 bug 需要多少局才能被 z 檢定偵測到

## 成果

- 一個指令（`python validate.py`）約 75 秒就能跑完 11 項驗收，產出含版本、設定雜湊、種子、局數的報告
- 16 項回歸測試約 5 秒
- 理論 RTP 96.6506%；5,292 萬局的模擬結果 96.672% ± 0.100%
